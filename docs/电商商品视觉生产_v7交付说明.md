## 2. 为什么第七版做「拆层 + 图层面板」？

### 2.1 原则（延续 v1～v6）

1. **每版可演示**：验收题是「点拆层 → 面板出现背景/主体 → 隐藏主体只剩背景」，不是半成品 JSON。  
2. **算法与工具分离**：`edits/split.py` 只管像素拆分/填洞；`tools/layers.py` 走 Registry。  
3. **复用异步闭环**：`split_layers` 入队 → Worker → SSE → 刷新会话与画布。  
4. **文档向后兼容**：未拆层时仍可只有 `layer_main`；拆层后替换为 `layer_background` + `layer_subject`。  
5. **演示优先、依赖可控**：拆层算法以现有 mock 去背 + 本地填洞为主，**不强制** OpenCV / rembg / 云端 inpaint。

### 2.2 v7 明确不做（留给后续 / 增强）

| 不做 | 放到哪 | 原因 |
|------|--------|------|
| 强制登录、COS、应用 Docker | v8 | 不阻塞图层主路径 |
| `promote_object_to_layer`（选区提升为物体层 + AI 填洞） | 增强 | 依赖选区×填洞链路，范围大 |
| OCR 文字层、矢量字层 | 增强 | 参考仓有，本仓非电商主演示 |
| 图层拖拽位移 / 缩放 / 旋转 UI | 增强 | 变换模型加重 |
| 图层透明度滑条、混合模式 | 增强 | 一期显隐即可 |
| rembg / SAM / 真实云端 matting | 增强 | 保持 mock 可离线演示 |
| 参考仓完整 `LayerDocument`（TEXT/SHAPE/locked 全套） | 不做 | 按本仓 JSON 渐进扩展 |

## 3. 第 7 版要完成什么？（验收标准）

完成 v7 后，你应能：

1. 工具栏（或面板入口）有 **拆层**（工具名建议 `split_layers`）。  
2. 执行后会话 `document.layers` 至少含 **背景**、**主体** 两层，各有独立 `asset_id`。  
3. 前端出现极简 **LayerPanel**：列出图层名、可见开关、当前选中层。  
4. **CanvasStage** 自下而上叠层渲染；隐藏某一层后画布立即变化。  
5. 整图类工具（提亮 / 翻转 / 去背）默认作用于 **当前选中层**（或「最上层可见图像层」，见 §14）。  
6. **导出** 将可见层合成为一张 PNG（扁平化），行为可演示。  
7. （建议）Agent Mock：goal 含「拆层/分出主体」时规划 `split_layers`。  
8. 选区局部提亮在多层下仍可用（至少：对当前层读选区合成；见 §14）。  
9. README 补充拆层与图层面板说明；分支 `version7`，tag `v7.0.0`。

**验收一句话**：上传商品图 → 点拆层 → 面板有「背景」「主体」→ 关掉主体 → 画布只剩背景。

## 4. 主流程（用户路径）

```text
用户点「拆层」
  → POST /api/sessions/{id}/tools/split_layers
  → tool_runs queued → ARQ

Worker：
  → 读取当前画布扁平图（未拆层：主图层；已拆层：可见层合成）
  → edits/split：
       subject_png  = 去背（复用/封装 mock_remove_background）
       mask         = 主体 alpha
       background   = 挖空主体后本地填洞（blur inpaint，无 OpenCV 也可）
  → 写两个 Asset，更新 document.layers = [背景, 主体]
  → 去掉原 layer_main（若存在）
  → SSE completed

前端：
  → reloadSession
  → LayerPanel 显示两层
  → Canvas 叠层绘制

用户在 LayerPanel 取消「主体」可见
  → PATCH 图层可见性（或专用 API）
  → 画布只显示背景
```

## 6. 后端：v7 要完成哪些文件？

### 6.1 `document.layers` 扩展（冻结）

**拆层前**（与现网兼容）：

```json
{
  "id": "layer_main",
  "name": "主图层",
  "asset_id": "...",
  "asset_key": "...",
  "visible": true
}
```

**拆层后**（建议）：

```json
{
  "version": 1,
  "canvas": { "width": 1024, "height": 1024 },
  "layers": [
    {
      "id": "layer_background",
      "name": "背景",
      "asset_id": "...",
      "asset_key": "...",
      "visible": true,
      "locked": true
    },
    {
      "id": "layer_subject",
      "name": "主体",
      "asset_id": "...",
      "asset_key": "...",
      "visible": true,
      "locked": false
    }
  ],
  "active_layer_id": "layer_subject",
  "selection": null
}
```

约定：

- 图层数组 **从下到上**（index 0 = 最底）。  
- `active_layer_id`：当前编辑目标；缺省时取最上层可见图像层。  
- v7 **不做** transform（x/y/scale）；主体与背景同画布尺寸叠放即可（与参考仓「全画幅主体层」简化版一致）。

### 6.2 `edits/split.py`（对齐参考仓，裁剪）

| 函数 | 职责 |
|------|------|
| `already_split(document)` | 是否已含背景+主体 |
| `split_to_subject_background(source_bytes)` | 去背得主体；挖空+填洞得背景 |
| `alpha_mask(subject_png)` | 从主体 alpha 取掩膜 |
| `fill_background(source, mask)` | 本地 blur 填洞（可选 cv2，失败则兜底） |

**不做**：OCR 去字、`promote_document`、云端 `_fill_hole`。

### 6.3 工具：`split_layers`

| 项 | 说明 |
|----|------|
| name | `split_layers` |
| label | 拆层 |
| params | 可空；预留 `force: bool`（已拆是否重拆，默认跳过） |
| 行为 | 已拆则幂等返回；否则写两资产并替换 layers |
| ui_exposed / agent_exposed | True |

### 6.4 现有工具适配

| 工具 | v7 行为 |
|------|---------|
| `adjust_image` / `flip_layer` / `remove_background` / `adjust_region` | 读写 **active 层**（或最上层可见层），写回该层 `asset_id` |
| `export` | 可见层自下而上 alpha 合成后下载 |

### 6.5 会话图层 API（建议）

| 方法 | 路径 | 说明 |
|------|------|------|
| PATCH | `/api/sessions/{id}/layers` | 更新 `visible` / `active_layer_id`（body 精简） |
| GET | `/api/sessions/{id}` | 已有，返回完整 document |

### 6.6 Agent 增量（轻量，建议做）

- 画布上下文增加：图层列表（id/name/visible）与是否已拆层。  
- Mock：含「拆层」「分出主体」「分离背景」→ `split_layers`。  
- Prompt：已拆层时不要重复拆；需要改某一层时说明当前层。

### 6.7 与参考仓库的对齐与差异

| 点 | 参考仓库 | image100 v7 |
|----|----------|-------------|
| `split_layers` | 去背 + 云端填洞 + 可选文字层 | **mock 去背 + 本地填洞**；无文字层 |
| `promote_object_to_layer` | 有 | **不做** |
| Layer 模型 | kind/transform/locked/text | **精简**：id/name/asset/visible/locked |
| LayerPanel | 完整 | **极简**：列表 + 显隐 + 选中 |
| 渲染 | 服务端 document 合成 | **前端 Konva 叠层** + 导出时后端/前端合成（择一，见 §14） |

## 9. v7 推荐开发顺序

1. 冻结拆层后 `layers` / `active_layer_id` 形状。  
2. `edits/split.py`：单测/脚本验一张图 → 主体透明、背景无大洞。  
3. 注册 `split_layers`；`runs` 支持按 layer_id 读写资产。  
4. 改造现有工具写回「目标层」。  
5. 导出扁平化。  
6. 前端 Canvas 多层 + LayerPanel + PATCH。  
7. Agent mock/prompt。  
8. README、联调、提交 `version7` / tag `v7.0.0`。
