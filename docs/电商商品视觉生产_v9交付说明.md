# 电商商品视觉生产 — 第 9 版（v9）交付说明

> **产品定位**：面向中小电商卖家 / 运营的「自然语言电商修图工作台」  
> **工程代号**：`image100`  
> **文档版本**：v9.0（2026-10-19）  
> **对应里程碑**：原规划 M7「部署硬化」**继续改口径** — 本期不做 Docker  
> **一句话目标**：**按已迁入的前端页面，补齐/接通后端能力与接口；必要时对照原仓库实现；Docker 顺延**  
> **关联文档**：  
> - `电商商品视觉生产_v8交付说明.md`、`v8_第八版完成总结.md`、`v8_API对照表.md`  
> - 参考仓库：[yuyuanweb/ai-picture-editor](https://github.com/yuyuanweb/ai-picture-editor)（**后端工具/路由/领域逻辑按需对照**，不整仓复制）  
> **协作方式**：从 `version8` 拉出 `version9`，完成后打 tag `v9.0.0` 并推送 GitHub

---

## 1. v9 在整条版本线里的位置（口径）

```text
v8：原仓前端 + 已实现 API 对齐 + COS
              ↓
★ v9：按前端页面补后端（本文）—— 不做 Docker
              ↓
v10+：Docker / 真登录硬化 / 剩余云端能力 …
```

| 版本 | 原规划 | **本期实际** |
|------|--------|--------------|
| v8 | 前端迁入 + COS | 已交付；大量前端入口仍占位或 404/501 |
| **v9（本文）** | ~~Docker~~ | **按页面补后端**：编辑器缺口工具、历史撤销、营销图、批量 … |
| v10+ | Docker 等 | Docker / compose / nginx；（可选）真鉴权强化 |

**原则**：

1. **前端页面驱动**：以当前 `frontend` 路由与工具栏/面板实际调用为准，缺什么后端补什么。  
2. **对照原仓、落本地仓**：算法/契约优先参考原仓同名工具与路由；落点仍在本仓 `ToolRegistry` / ARQ / document JSONB / COS。  
3. **不做 Docker**（用户明确要求）。  
4. **不做整仓后端复制**；不推倒本仓 Agent/生图架构。

---

## 2. 为什么第九版这样做？

v8 已把原仓 UI 接上本仓「已有」能力。前端上仍大量入口指向未实现后端：

| 前端区域 | 现状（v8 末） | v9 目标 |
|----------|---------------|---------|
| Editor 工具栏 | 裁剪/换背景/扩图/超分等会失败；选区仅笔刷+局部提亮 | 按优先级接通原仓同名工具 |
| 图层面板 | 显隐可用；透明度/变换/文字/排序多未实现 | 补图层类工具或同步 PATCH |
| 撤销/重做 | 501 | 会话 history + undo/redo |
| `/marketing` | 占位页 | 恢复页面 + `generate_marketing` 等 |
| `/batch` | 占位页 | 恢复页面 + batches API |
| 点选 | 501 | mock 或简化实现（全量 SAM 可降级） |
| Docker | — | **明确不做** |

## 3. 第 9 版要完成什么？（验收标准）

### 3.1 必须：编辑器「前端已暴露」的核心缺口

以工具栏 / 图层面板 / 快捷键实际调用为准，下列能力需可演示（实现深度允许 mock/本地算法，契约对齐原仓）：

| 能力 | 前端入口（约） | 建议对照原仓 |
|------|----------------|--------------|
| 会话撤销 / 重做 | `undo` / `redo`、⌘Z | `sessions` history |
| 裁剪 | `crop_canvas` | `tools/canvas` |
| 超分 | `upscale_image` | `tools/enhance` |
| 换背景 | `replace_background` | `tools/generate` / retouch |
| 扩图 | `expand_canvas` | 同上 |
| 局部消除 | `erase_region`（选区后） | `tools/region` |
| 局部替换 | `replace_region` | `tools/region` |
| 图层变换类 | `move/scale/rotate/opacity/reorder` 等 | `tools/layers` / canvas |
| 成层 | `promote_object_to_layer` | `tools/layers` |

验收：点对应按钮不再 404；有进度（SSE）；画布/会话刷新正确；失败有明确文案。

### 3.2 必须：营销图页接通

1. `App` 恢复 `MarketingPage`（去掉 ComingSoon）。  
2. 后端提供原仓前端所需：`generate_marketing`、`prepare_delivery_sizes`（及导出若页内依赖）。  
3. 主路径：选会话 → 生成营销素材 → 可见候选/挂墙 → 可导出（按页内实际交互）。

### 3.3 必须：批量页接通

1. 恢复 `BatchPage`。  
2. 后端 `POST/GET /batches`、进度/SSE 或轮询、导出（对照原仓 `batches` 路由与 `tools/batch`）。  
3. 主路径：选图 → 选操作 → 跑批 → 看结果（允许部分操作为本仓已实现工具子集）。

### 3.4 建议：点选选区

- 原仓为 SAM/点选；本期可用 **mock 洪水填充 / 简化点选** 生成 mask，契约对齐 `prepare` + `selection` points。  
- 若工作量过大，可在 §13 选「降级：点选继续提示后续版本」，把预算留给营销/批量。

### 3.5 明确不做（本期）

| 不做 | 说明 |
|------|------|
| Docker / compose / nginx | 用户要求暂缓 → v10+ |
| 整仓复制原仓后端 / ORM | 本仓架构保留 |
| 真登录强制（JWT 替换演示桩） | 默认仍 demo；可选增强不作为 DoD |
| 原仓全部 21 工具一次做完 | 按前端入口优先级；未列入口可继续隐藏或 toast |

**验收一句话**：编辑器前端暴露的主按钮可跑通；营销图、批量两页不再占位且后端可演示；仍无 Docker。

## 5. 建议实现顺序

1. **会话 history + undo/redo**（编辑器体验基础）。  
2. **编辑器高优先级工具**：`crop_canvas`、`upscale_image`、`erase_region`、`replace_region`、`promote_object_to_layer`。  
3. **生成类**：`replace_background`、`expand_canvas`（可 mock 或 DashScope，按环境）。  
4. **图层变换**：move / scale / rotate / opacity / reorder / set_layer_text（与面板对齐）。  
5. **Marketing 页** 恢复 + 工具。  
6. **Batch 页** 恢复 + API（操作子集 = 本仓已注册工具）。  
7. **点选**（或确认降级）。  
8. 更新 `v8_API对照表` → `v9_API对照表`、README；tag `v9.0.0`。
