## 4. 后端完成了什么？

### 4.1 能力清单

1. 用 `pydantic-settings` 从项目根 `.env` 读取配置，业务代码不散落 `os.getenv`。  
2. SQLAlchemy 异步引擎连接虚拟机 PostgreSQL；`redis.asyncio` 连接虚拟机 Redis。  
3. 提供 `GET /api/health`：并行探测 PG + Redis，返回结构化 JSON。  
4. CORS 允许前端 `7301` 源；Swagger 在 `/api/docs`。  
5. 依赖通过 `backend/pyproject.toml` 声明，可用 `pip install -e .` 安装。

### 4.2 依赖（`backend/pyproject.toml`）

| 包 | 用途 |
|----|------|
| `fastapi` | Web 框架 |
| `uvicorn[standard]` | ASGI 服务器 |
| `pydantic-settings` | 环境变量 / `.env` 配置 |
| `sqlalchemy[asyncio]` + `asyncpg` | 异步访问 PostgreSQL |
| `redis` | 异步访问 Redis |
| `httpx` | 预留 HTTP 客户端（v1 业务未用，为后续调用外部 API 准备） |

要求：`requires-python >= 3.13`（本机 conda 环境 `image100` 为 3.13.16）。

### 4.3 环境变量（生效项）

| 变量 | 含义 | 默认/示例 |
|------|------|-----------|
| `APP_ENV` | 运行环境 | `development` |
| `API_PORT` | API 端口 | `7302` |
| `DATABASE_URL` | 异步 PG 连接串 | `...@192.168.137.128:7311/retouch` |
| `REDIS_URL` | Redis 连接串 | `redis://192.168.137.128:7312/0` |
| `CORS_ORIGINS` | 允许的前端源（逗号分隔） | `http://localhost:7301,http://127.0.0.1:7301` |

`.env.example` 中还用**注释**预留了 JWT、本地存储 / 腾讯云 COS、DashScope 模型等，v1 的 `Settings` **不读取**这些字段。

### 4.4 健康检查约定

请求：`GET http://127.0.0.1:7302/api/health`

成功示例：

```json
{
  "status": "ok",
  "postgres": "ok",
  "redis": "ok"
}
```

规则：

- HTTP 状态码**始终 200**（方便前端与探活脚本解析 body）。  
- 单项：`"ok"` 或 `"error"`（不回传异常细节，避免泄露）。  
- 任一依赖失败：整体 `"status": "degraded"`。

## 5. 后端每个 Python 文件详解

### 5.1 `backend/app/__init__.py`

- **内容**：包标识与简短模块说明。  
- **作用**：把 `app` 声明为 Python 包，便于 `uvicorn app.main:app` 与 `from app.xxx import ...`。  
- **联动**：无业务逻辑；被整个后端包依赖。

---

### 5.2 `backend/app/config.py` — 配置中心

**做什么**

- 定义 `Settings`（继承 `BaseSettings`），集中管理 v1 生效配置。  
- 从**项目根目录**的 `.env` 加载（`ROOT_DIR = Path(__file__).resolve().parents[2]`，即 `image100/`）。  
- `get_settings()` 用 `@lru_cache` 做成进程内单例。  
- `cors_origins` 使用 `NoDecode` + 校验器，支持逗号分隔字符串（避免被当成 JSON 解析失败）。  
- `extra="ignore"`：`.env` 里多余或注释预留项不会报错。

**核心字段**

- `app_env`、`api_port`、`database_url`、`redis_url`、`cors_origins`  
- 属性 `is_production`：判断是否生产环境（v1 几乎未用，供后续）。

**被谁调用**

| 调用方 | 用法 |
|--------|------|
| `db.py` | `get_settings()` 取 `database_url` / `redis_url` 建连接 |
| `main.py` | `get_settings()` 取 `cors_origins` 配 CORS |
| `deps.py` | 包装为 `get_app_settings` / `SettingsDep` 给路由注入 |

**设计原则**：全项目禁止在业务里直接 `os.getenv`；以后加配置只改 `Settings` 和 `.env.example`。

---

### 5.3 `backend/app/db.py` — 数据层与连通探测

**做什么**

1. 根据配置创建异步引擎：  
   `engine = create_async_engine(settings.database_url, pool_pre_ping=True)`  
2. 创建 Session 工厂：`SessionFactory = async_sessionmaker(...)`  
3. 预留 ORM 基类 `Base(DeclarativeBase)`（v2 起业务表继承它）。  
4. `get_session()`：异步生成器，按请求提供 `AsyncSession`。  
5. `check_postgres()`：执行 `SELECT 1`，成功 `"ok"`，异常 `"error"`。  
6. `check_redis()`：`PING`，成功 `"ok"`，异常 `"error"`，并在 `finally` 关闭客户端。

**被谁调用**

| 调用方 | 用法 |
|--------|------|
| `deps.py` | `get_db` 内部转调 `get_session` |
| `routers/health.py` | 并行调用 `check_postgres` / `check_redis` |

**注意**：v1 **没有**建业务表、没有 Alembic；health 只验证「网络 + 账号 + 服务活着」，不验证表结构。

---

### 5.4 `backend/app/deps.py` — 依赖注入入口

**做什么**

- `get_app_settings()` → 返回配置单例。  
- `get_db()` → yield 数据库 Session（封装 `db.get_session`）。  
- 类型别名：  
  - `SettingsDep = Annotated[Settings, Depends(get_app_settings)]`  
  - `DbDep = Annotated[AsyncSession, Depends(get_db)]`

**作用**

- 给后续路由提供统一写法，例如：`async def foo(db: DbDep, settings: SettingsDep)`。  
- v1 的 `health` 路由目前**直接**调 `db.check_*`，尚未使用 `DbDep`；`deps.py` 是为 v2+ 预留的「正规入口」。

**联动**

```text
deps.get_app_settings  →  config.get_settings
deps.get_db            →  db.get_session
```

---

### 5.5 `backend/app/schemas/__init__.py` 与 `schemas/common.py`

**`__init__.py`**：schemas 包标识。

**`common.py` — `HealthResponse`**

| 字段 | 含义 |
|------|------|
| `status` | 整体：`ok` / `degraded` |
| `postgres` | `ok` / `error` |
| `redis` | `ok` / `error` |

**作用**

- 作为 FastAPI `response_model`，约束响应形状，并生成 OpenAPI 文档。  
- 前端 `HealthResponse` TypeScript 接口与此对齐。

**被谁调用**：`routers/health.py` 的返回类型。

---

### 5.6 `backend/app/routers/__init__.py` — 路由汇总

**做什么**

```python
api_router = APIRouter()
api_router.include_router(health.router)
```

**作用**：以后加 `assets`、`sessions` 等路由，只在这里 `include_router`，`main.py` 不用改挂载逻辑。

**联动**：被 `main.py` 以 `prefix="/api"` 挂载 → 最终路径形如 `/api/health`。

---

### 5.7 `backend/app/routers/health.py` — 健康检查接口

**做什么**

- 定义 `router = APIRouter(tags=["health"])`。  
- 路由：`GET /health`（加上 main 的 `/api` 前缀后为 `/api/health`）。  
- 用 `asyncio.gather` **并行**探测 PG 与 Redis。  
- 组装 `HealthResponse` 返回。

**代码逻辑（简述）**

1. `postgres_status, redis_status = await asyncio.gather(check_postgres(), check_redis())`  
2. 两者都是 `"ok"` → `status="ok"`，否则 `status="degraded"`  
3. 返回 Pydantic 模型（FastAPI 序列化为 JSON）

**联动**

```text
HTTP 请求
  → main.app（CORS / 路由前缀）
  → routers.api_router
  → health.health_check
  → db.check_postgres / db.check_redis
  → schemas.HealthResponse
```

路由层保持很薄：只编排探测与组装响应，不写连接细节。

---

### 5.8 `backend/app/main.py` — 应用入口

**做什么**

- `create_app()` 工厂：创建 `FastAPI`、挂 CORS、挂 `api_router`。  
- 模块级 `app = create_app()`，供 uvicorn 加载：`uvicorn app.main:app`。  
- OpenAPI：`docs_url="/api/docs"`，`openapi_url="/api/openapi.json"`。  
- 应用标题：`电商商品视觉 image100`。

**CORS**

- `allow_origins=settings.cors_origins`  
- 允许凭证、所有方法与头（开发期宽松；生产可收紧）。

**联动**

```text
uvicorn
  → app.main:app
  → create_app()
       ├─ get_settings()          # config
       ├─ CORSMiddleware
       └─ include_router(api_router, prefix="/api")  # routers
```

**一次完整 health 请求的时序**

1. 客户端请求 `GET /api/health`。  
2. `main.app` 匹配前缀 `/api`，交给 `api_router`。  
3. `health_check` 并行调用 `check_postgres`、`check_redis`。  
4. `check_postgres` 用 `SessionFactory` 连 `DATABASE_URL` 执行 `SELECT 1`。  
5. `check_redis` 用 `REDIS_URL` 执行 `PING`。  
6. 组装 `HealthResponse`，JSON 返回；Swagger 亦可在 `/api/docs` 试调。

## 7. 前端完成了什么？

### 7.1 能力清单

1. Vite + React 19 + TypeScript 工程可 `npm run dev` / `npm run build`。  
2. 开发服务器固定 `127.0.0.1:7301`，`/api` 代理到 `http://127.0.0.1:7302`。  
3. `react-router-dom`：`/` 落地页，其它路径重定向到 `/`。  
4. 落地页展示品牌「image100 / 电商商品视觉」、一句话介绍、系统状态（整体 / PostgreSQL / Redis）。  
5. `api/client.ts` 封装 `getHealth()`，为后续接口封装打样。

### 7.2 前端关键文件说明

| 文件 | 内容与作用 |
|------|------------|
| `package.json` | 依赖：`react`、`react-dom`、`react-router-dom`；脚本 `dev` / `build` / `preview` |
| `vite.config.ts` | React 插件；端口 7301；`proxy['/api'] → 7302` |
| `index.html` | `#root` 挂载点；标题「电商商品视觉 · image100」 |
| `src/main.tsx` | `StrictMode` + `BrowserRouter` 渲染 `App` |
| `src/App.tsx` | 路由表：仅 `LandingPage` |
| `src/index.css` | 落地页全局样式（简洁渐变背景 + 状态列表） |
| `src/api/client.ts` | `HealthResponse` 类型 + `getHealth()` |
| `src/pages/LandingPage.tsx` | 产品文案 + 拉取并展示 health |

**未引入（刻意）**：Konva、Zustand、TanStack Query、编辑器页、登录页等。

### 7.3 前端如何与后端联动

```text
浏览器打开 http://127.0.0.1:7301/
  → main.tsx → App → LandingPage
  → useEffect 调用 getHealth()
  → fetch('/api/health')          # 相对路径，同源到 Vite
  → Vite 代理转发到 127.0.0.1:7302/api/health
  → 后端 health 探测 PG/Redis
  → JSON 返回前端
  → LandingPage 渲染 status / postgres / redis
```

三种加载态：

| 状态 | 页面表现 |
|------|----------|
| `loading` | 「正在检测后端连通性…」 |
| `ready` | 展示三项状态徽章 |
| `failed` | 展示错误信息（后端未启动或代理失败等） |

`useEffect` 带取消标记，避免组件卸载后仍 `setState`。
