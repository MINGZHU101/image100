## 4. 后端完成了什么？

### 4.1 能力清单

1. 用 `pydantic-settings` 从项目根 `.env` 读取配置，业务代码不散落 `os.getenv`。  
2. SQLAlchemy 异步引擎连接虚拟机 PostgreSQL；`redis.asyncio` 连接虚拟机 Redis。  
3. 提供 `GET /api/health`：并行探测 PG + Redis，返回结构化 JSON。  
4. CORS 允许前端 `7301` 源；Swagger 在 `/api/docs`。  
5. 依赖通过 `backend/pyproject.toml` 声明，可用 `pip install -e .` 安装。

### 4.2 依赖（`backend/pyproject.toml`）

| 包 | 用途 |
|----|------|
| `fastapi` | Web 框架 |
| `uvicorn[standard]` | ASGI 服务器 |
| `pydantic-settings` | 环境变量 / `.env` 配置 |
| `sqlalchemy[asyncio]` + `asyncpg` | 异步访问 PostgreSQL |
| `redis` | 异步访问 Redis |
| `httpx` | 预留 HTTP 客户端（v1 业务未用，为后续调用外部 API 准备） |

要求：`requires-python >= 3.13`（本机 conda 环境 `image100` 为 3.13.16）。

### 4.3 环境变量（生效项）

| 变量 | 含义 | 默认/示例 |
|------|------|-----------|
| `APP_ENV` | 运行环境 | `development` |
| `API_PORT` | API 端口 | `7302` |
| `DATABASE_URL` | 异步 PG 连接串 | `...@192.168.137.128:7311/retouch` |
| `REDIS_URL` | Redis 连接串 | `redis://192.168.137.128:7312/0` |
| `CORS_ORIGINS` | 允许的前端源（逗号分隔） | `http://localhost:7301,http://127.0.0.1:7301` |

`.env.example` 中还用**注释**预留了 JWT、本地存储 / 腾讯云 COS、DashScope 模型等，v1 的 `Settings` **不读取**这些字段。

### 4.4 健康检查约定

请求：`GET http://127.0.0.1:7302/api/health`

成功示例：

```json
{
  "status": "ok",
  "postgres": "ok",
  "redis": "ok"
}
```

规则：

- HTTP 状态码**始终 200**（方便前端与探活脚本解析 body）。  
- 单项：`"ok"` 或 `"error"`（不回传异常细节，避免泄露）。  
- 任一依赖失败：整体 `"status": "degraded"`。

### 5.1 `backend/app/__init__.py` — 应用包入口标记

| 项 | 说明 |
|----|------|
| **一句话** | 告诉 Python：「`app` 是一个包」。 |

| **联动** | 被整个 `backend/app/` 目录下的模块隐式依赖。 |
| **怎么读** | 扫一眼即可，不用深挖。 |

---

### 5.2 `backend/app/config.py` — 全项目配置中心

| 项 | 说明 |
|----|------|
| **一句话** | 只在这里读 `.env` / 环境变量，别处禁止随便 `os.getenv`。 |

**文件里有什么**

1. `ROOT_DIR`：根据本文件位置算出**项目根** `image100/`（往上两级：`app/` → `backend/` → 根）。  
2. 类 `Settings(BaseSettings)`：用 pydantic-settings 声明配置字段。  
3. `get_settings()`：带 `@lru_cache`，进程内只解析一次配置。  

**v1 生效字段（含义）**

| 字段 | 对应环境变量 | 干什么用 |
|------|--------------|----------|
| `app_env` | `APP_ENV` | 环境名，如 development |
| `api_port` | `API_PORT` | 文档/约定端口 7302（真正监听由 uvicorn 命令决定） |
| `database_url` | `DATABASE_URL` | 异步 PG 连接串（含 IP、端口、库名、账号） |
| `redis_url` | `REDIS_URL` | Redis 连接串 |
| `cors_origins` | `CORS_ORIGINS` | 允许跨域的前端地址列表 |

**关键实现细节**

- `.env` 路径是 `ROOT_DIR / ".env"`，所以配置文件放在仓库根，而不是 `backend/` 下。  
- `cors_origins` 用了 `NoDecode`：否则 pydantic-settings 会把  
  `http://localhost:7301,http://127.0.0.1:7301`  
  当成 JSON 解析而报错；再用校验器按逗号拆成 `list[str]`。  
- `extra="ignore"`：`.env.example` 里注释预留的 JWT/COS/模型变量，即使以后写进 `.env`，v1 的 Settings 也不会因为「未知字段」崩掉。  
- 属性 `is_production`：`app_env == "production"` 时为真（v1 几乎未用）。

**和谁联动**

| 谁调用它 | 取什么 |
|----------|--------|
| `db.py` | `database_url`、`redis_url` |
| `main.py` | `cors_origins` |
| `deps.py` | 封装成 `SettingsDep` 供路由注入 |

**怎么读**：先看 `Settings` 字段列表，再看 `get_settings()`；其他都是辅助。

### 5.3 `backend/app/db.py` — 数据库引擎 + 中间件探活

| 项 | 说明 |
|----|------|
| **一句话** | 创建连 PostgreSQL 的异步引擎，并提供「PG / Redis 是否活着」的探测函数。 |

**文件里有什么**

1. `engine`：`create_async_engine(...)`，驱动是 `asyncpg`（URL 里 `postgresql+asyncpg://`）。`pool_pre_ping=True` 表示取连接前先探活，减少「连接已被服务端掐掉」的报错。  
2. `SessionFactory`：`async_sessionmaker`，用来生产每次请求用的 `AsyncSession`。  
3. `Base(DeclarativeBase)`：ORM 表模型的基类（v1 还没有业务表，但先放好，v2 模型会继承它）。  
4. `get_session()`：`async with SessionFactory() as session: yield session`，给 FastAPI 依赖注入用。  
5. `check_postgres()`：开一个 session，执行 `SELECT 1`；成功返回 `"ok"`，任意异常返回 `"error"`（不把异常详情暴露给前端）。  
6. `check_redis()`：用 `redis.asyncio` 按 `REDIS_URL` 建客户端，`PING`；`finally` 里关闭连接。

**负责什么功能**

- **不是**业务 CRUD（v1 没有资产/会话表）。  
- **是**「能不能连上虚拟机上的 PG:7311 和 Redis:7312」。

**和谁联动**

| 谁调用它 | 怎么用 |
|----------|--------|
| `deps.get_db` | 转调 `get_session` |
| `routers/health.py` | 并行调用 `check_postgres` / `check_redis` |

**怎么读**：先看顶部 engine/SessionFactory，再看两个 `check_*`；中间 `Base` 留给以后。

---

### 5.4 `backend/app/deps.py` — FastAPI 依赖注入「插座」

| 项 | 说明 |
|----|------|
| **一句话** | 把「取配置」「取数据库 Session」包装成路由参数里可直接写的类型。 |

**文件里有什么**

- `get_app_settings()` → 调 `config.get_settings()`。  
- `get_db()` → `async for session in get_session(): yield session`。  
- `SettingsDep = Annotated[Settings, Depends(get_app_settings)]`  
- `DbDep = Annotated[AsyncSession, Depends(get_db)]`

**负责什么功能**

- 让以后写路由时可以：  
  `async def foo(db: DbDep, settings: SettingsDep): ...`  
  而不用在每个函数里手动 `get_settings()` / 开 session。  
- **v1 实际情况**：`health` 路由还没用 `DbDep`（它直接调 `db.check_*`）；本文件主要是**为 v2 上传/会话路由预留正规入口**。

**联动关系（简化）**

```text
路由参数 DbDep
  → deps.get_db
  → db.get_session
  → SessionFactory → PostgreSQL
```

**怎么读**：看两个 `Annotated` 别名即可；明白「Depends 会在进路由前自动执行」。

### 5.7 `backend/app/routers/__init__.py` — API 路由「总闸」

| 项 | 说明 |
|----|------|
| **一句话** | 把各个子路由模块挂到同一个 `api_router` 上。 |

**文件里有什么**

```python
api_router = APIRouter()

```

**负责什么功能**

- v1 只挂了 health。  
- 以后加 `assets`、`sessions` 时，**只改这个文件**多写一行 `include_router`，`main.py` 不用动挂载逻辑。

```text

  → 本文件的 api_router
  → health.router  → 最终路径 /api/health
```

**怎么读**：看 `include_router` 列表就知道当前开放了哪些业务模块。

### 5.8 `backend/app/routers/health.py` — 健康检查 HTTP 接口

| 项 | 说明 |
|----|------|
| **一句话** | 对外提供 `GET /api/health`，回报中间件是否可用。 |

**文件里有什么**

- `router = APIRouter(tags=["health"])`：Swagger 里归到 health 分组。  
- 异步函数 `health_check()`，装饰器：`@router.get("/health", response_model=HealthResponse)`。

**负责什么功能（逐步）**

1. 用 `asyncio.gather` **同时**跑 `check_postgres()` 和 `check_redis()`（并行，少等一会儿）。  
2. 两个都是 `"ok"` → 整体 `status="ok"`，否则 `"degraded"`。  
3. 组装 `HealthResponse` 返回。  
4. **约定**：即使某依赖挂了，HTTP 状态码仍是 **200**，靠 body 里的字段判断；这样探活脚本和前端解析更简单，也不会把内部异常栈甩给浏览器。

**不负责什么**

- 不自己拼数据库 URL、不开 Redis 连接细节（那些在 `db.py`）。  
- 不做鉴权、不读写业务表。

**联动（一次请求怎么走）**

```text
浏览器/curl
  → main.app（CORS、/api 前缀）
  → routers/__init__.py 的 api_router
  → health.health_check
  → db.check_postgres / db.check_redis
  → schemas.HealthResponse → JSON
```

**怎么读**：从 `health_check` 函数从上往下读 10 行就能懂整个接口。

### 5.9 `backend/app/main.py` — FastAPI 应用组装入口

| 项 | 说明 |
|----|------|
| **一句话** | 创建整个 Web 应用对象：标题、文档地址、CORS、挂上 `/api` 路由。 |

**文件里有什么**

1. `create_app()` 工厂函数：  
   - `FastAPI(title=..., docs_url="/api/docs", openapi_url="/api/openapi.json")`

2. 模块级 `app = create_app()`：给命令行用。

**负责什么功能**

**联动**

```text

  → app.main:app
  → create_app()

       └─ routers.api_router        # 当前只有 health
```

**怎么读**：先看 `create_app` 里三步（建应用 → CORS → 挂路由），再看最后一行 `app = create_app()`。

**一次完整 health 请求的时序**

1. 客户端请求 `GET /api/health`。

4. `check_postgres` 用 `SessionFactory` 连 `DATABASE_URL` 执行 `SELECT 1`。  
5. `check_redis` 用 `REDIS_URL` 执行 `PING`。  
6. 组装 `HealthResponse`，JSON 返回；Swagger 亦可在 `/api/docs` 试调。

| `src/api/client.ts` | `HealthResponse` 类型 + `getHealth()` |
| `src/pages/LandingPage.tsx` | 产品文案 + 拉取并展示 health |

**未引入（刻意）**：Konva、Zustand、TanStack Query、编辑器页、登录页等。

### 7.3 前端如何与后端联动

```text
浏览器打开 http://127.0.0.1:7301/
  → main.tsx → App → LandingPage
  → useEffect 调用 getHealth()
  → fetch('/api/health')          # 相对路径，同源到 Vite
  → Vite 代理转发到 127.0.0.1:7302/api/health
  → 后端 health 探测 PG/Redis
  → JSON 返回前端
  → LandingPage 渲染 status / postgres / redis
```

三种加载态：

| 状态 | 页面表现 |
|------|----------|
| `loading` | 「正在检测后端连通性…」 |
| `ready` | 展示三项状态徽章 |
| `failed` | 展示错误信息（后端未启动或代理失败等） |

`useEffect` 带取消标记，避免组件卸载后仍 `setState`。

## 8. 端口与部署关系（v1）

| 服务 | 端口 | 运行位置 |
|------|------|----------|
| 前端 Vite | 7301 | Windows 本机 |
| 后端 FastAPI | 7302 | Windows 本机 |
| PostgreSQL | 7311→5432 | 虚拟机 Docker（如 `192.168.137.128`） |
| Redis | 7312→6379 | 虚拟机 Docker |

开发期数据流：

```text
浏览器 → 前端:7301 →（代理）→ 后端:7302 → 虚拟机 PG/Redis
```

应用整体进虚拟机 Docker 属于后续版本（约 v8），不在 v1 范围。
