## 2. 为什么第六版做「选区 + 局部调色」？

### 2.1 原则（延续 v1～v5）

1. **每版可演示**：验收题是「框一块区域 → 局部提亮 → 只有选区内变亮」，不是半截 overlay。  
2. **选区先本地、再落库**：前端交互实时；确认工具调用前把选区同步到 `document.selection`（或随工具 params 提交）。  
3. **算法与工具分离**：`edits/mask.py` 只管栅格化/合成；`tools/region.py`（或等价）走 Registry。  
4. **复用异步闭环**：局部工具仍 `POST .../tools/{name}` → Worker → SSE → 刷新画布。  
5. **Agent 可感知选区（轻量）**：有选区时 mock/LLM 可规划 `adjust_region`；无选区则提示先框选或退回整图 `adjust_image`。

### 2.2 v6 明确不做（留给后续版本）

| 不做 | 放到哪一版 | 原因 |
|------|------------|------|
| 主体/背景拆层、完整 LayerPanel | v7 | 图层模型加重 |
| 强制登录、COS、应用 Docker | v8 / 增强 | 不阻塞选区主路径 |
| `erase_region` / `replace_region`（AI 局部消除/替换） | 增强 | 依赖图生图编辑模型，范围大 |
| SAM / 智能点击选区 | 增强 | 重依赖 |
| 魔术棒、羽化 UI 全套、选区运算（加/减/交） | 增强 | 一期矩形+笔刷够演示 |
| 参考仓库全量 CanvasStage 选区逻辑整文件移植 | 不做 | 按本仓 Konva 结构裁剪实现 |

## 3. 第 6 版要完成什么？（验收标准）

完成 v6 后，你应能：

1. 编辑器工具栏出现选区模式：**矩形**、**笔刷**、**清除选区**。  
2. 在画布上拖出矩形或涂抹笔画，有半透明 **选区 overlay** 可视化。  
3. 选区写入会话 `document.selection`（刷新/重进会话可恢复，或至少工具调用时后端能读到）。  
4. 新增局部工具（建议名 `adjust_region`）：仅对选区内做亮度/对比度/饱和度调整；选区外像素不变。  
5. 调用仍走 ARQ；完成后画布更新，选区可自动清空或保留（见 §14 默认项）。  
6. 无选区时调用局部工具 → 明确 4xx/中文提示「请先框选区域」。  
7. （建议）Agent mock：在有选区且 goal 含「局部提亮」时规划 `adjust_region`。  
8. README 补充选区操作说明；提交 `version6`，tag 建议 `v6.0.0`。

**验收一句话**：上传/生图进编辑器 → 矩形框商品局部 → 点「局部提亮」→ 只有框内变亮。

## 4. 主流程（用户路径）

```text
用户在 Editor 点「矩形选区」
  → 在 Canvas 上拖拽得到 rect（归一化 0～1 坐标）
  → 前端更新 overlay +（建议）PATCH session.document.selection

用户点「局部提亮」
  → POST /api/sessions/{id}/tools/adjust_region
       params: { brightness: 0.2, ... }  （选区以 document.selection 为准）
  → services/tools：写 tool_runs → ARQ enqueue → 返回 run_id

Worker：
  → 读主图层字节 + document.selection
  → edits/mask：栅格化为 L 掩膜
  → 对整图做 adjust → apply_masked(原图, 调色图, mask)
  → 写新 asset，更新 document.layers[0]
  → （可选）清空 selection
  → SSE completed

前端：刷新会话 / 画布
```

笔刷路径：笔画点列归一化 → `rasterize_strokes` → 同上合成。

## 6. 后端：v6 要完成哪些文件？

### 6.1 `document.selection` 形状（冻结）

会话里原有 `"selection": null`，v6 扩展为：

```json
{
  "type": "rect",
  "rect": { "x": 0.2, "y": 0.3, "width": 0.4, "height": 0.35 },
  "feather": 0
}
```

或笔刷：

```json
{
  "type": "brush",
  "strokes": [
    [[0.12, 0.40], [0.18, 0.42], [0.25, 0.41]]
  ],
  "brush_radius": 0.03,
  "feather": 0
}
```

约定：

- 坐标相对画布宽高，取值约 `0～1`（与参考仓库笔画归一化一致）。  
- `brush_radius` 相对短边比例。  
- `null` 表示无选区。

### 6.2 `edits/mask.py`（对齐参考仓库，裁剪）

| 函数 | 职责 |
|------|------|
| `rasterize_rect(size, rect)` | 矩形 → `L` 掩膜 |
| `rasterize_strokes(size, strokes, radius)` | 笔画闭合填涂 + 线宽（可简化自参考实现） |
| `apply_masked(source, edited, mask)` | 选区内用 edited，选区外保留 source |
| （可选）`overlay_png(mask)` | 调试/预览用半透明着色 |

**不做**：SAM、复杂选区布尔运算。

### 6.3 工具：`adjust_region`

| 项 | 说明 |
|----|------|
| name | `adjust_region` |
| label | 局部提亮（或「局部调色」） |
| params | 与 `adjust_image` 同：brightness/contrast/saturation |
| 行为 | 读 `document.selection` → 造 mask → 整图 adjust → `apply_masked` → 写回主图层 |
| ui_exposed | True |
| agent_exposed | True（建议） |
| 无选区 | 400 + 中文「请先框选或涂抹选区」 |

整图 `adjust_image` **保留**，行为不变（忽略选区）。

### 6.4 会话选区 API（建议）

| 方法 | 路径 | 说明 |
|------|------|------|
| PATCH | `/api/sessions/{id}/selection` | body = selection 对象或 `null` 清除 |
| GET | `/api/sessions/{id}` | 已有；返回含 selection 的 document |

也可仅在工具 params 里带 `selection` 快照（防并发过期）；**推荐落库**，便于刷新恢复与 Agent 读上下文。

### 6.5 Agent 增量（轻量，建议做）

- 画布上下文增加：`选区：有/无（rect|brush）`。  
- Mock：goal 含「局部」且有选区 → `adjust_region`；无选区 → reply 提示先框选。  
- DashScope：prompt 中写明「有选区时优先 adjust_region」。  

**不做**：图内自动生成选区。

### 6.6 与参考仓库的对齐与差异

| 点 | 参考仓库 | image100 v6 |
|----|----------|-------------|
| mask 栅格化 / apply_masked | `edits/mask.py` | **对齐思路**，按需精简 |
| SelectionOverlay | 有 | **对齐**矩形+笔刷 |
| region 工具 | erase/replace（云端 edit） | **只做局部调色**（Pillow） |
| 选区存储 | 独立 selection 服务 + mask asset | **优先 document.selection JSON**（更简单） |
| 图层×选区交集 | 多层 | **单主图层**即可 |
