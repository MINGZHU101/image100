## 2. 本版三大需求

### 2.1 文案生成（侧栏新入口）

| 项 | 口径 |
|----|------|
| 入口位置 | 工作台侧栏：**「创作」与「编辑」之间** 增加 **「文案生成」** |
| 路由建议 | `/copywriting` |
| 输入 | **提示词（文本）** 和/或 **商品图（可选上传 / 选已有素材）** |
| 输出 | 电商商品文案：标题 + 正文 + 标签（可再拆「卖点短句」等，实现时定稿） |
| 参考 | `demo04`：电商文案专家角色 + 思维链（人群痛点→卖点转化→情感文案→标签）；`demo03`：多阶段流式输出的交互节奏。**只借鉴思路，不照搬 ToT 四段策划或 LlamaIndex ChatMessage 写法** |
| 交互 | 本仓组件语言：表单 + 结果区；可选 **流式**（SSE）提升体感，非必须 1:1 复刻 demo03 |
| 鉴权 / 计费 | 需登录；扣积分（建议见 §5）；计入日 AI 配额；demo 账号不扣分 |

**不在本版**：独立「社媒周日历 / 爆款策划台」、多平台一键分发、文案版本历史大库（可顺延）。

### 2.2 文生图：多张时提示词改写 / 扩写

| 项 | 口径 |
|----|------|
| 问题 | 选择生成 **2 / 4 张**（及以后凡 `count ≥ 2`）时，当前 Provider 用**同一 prompt** 调接口，结果高度雷同，体验差 |
| 目标 | `count ≥ 2` 时，对用户原提示词做 **改写 + 扩写**，得到 **N 条语义相关但视角/构图/光影/卖点侧重不同** 的提示词，再分别生图（或带差异 seed/参数），保证候选图**肉眼可区分** |
| `count = 1` | 保持现状，不改写（或仅轻量清洗，默认不改写） |
| 落点 | 后端 Worker / `execute_generation` 主路径：在调用 `ImageProvider.generate` **之前**完成改写；前端可不感知细节，结果页仍展示多候选 |
| 可观测 | `GenerationRun.params` 可存 `prompt_variants: string[]`（便于排障）；流水备注可写「多图改写」 |

**建议算法（实现时二选一或组合，编码前可微调）**：

1. **LLM 一次产出 N 条变体**（推荐）：用本仓已有 DashScope / LangChain Chat，严格 JSON 数组输出；温度略高；约束「保留商品主体与核心卖点，改变角度/场景/风格细节」。  
2. **串行 N 次单图调用**：每条变体 `count=1` 调 Provider（比 `n=N` 同 prompt 更易出差异）。  
3. Mock Provider：变体文本不同即可改变占位图哈希，便于无 Key 演示。

**不在本版**：用户手动编辑每条变体 UI、A/B 评分闭环。

### 2.3 工作台 AI 智能客服（RAG）

| 项 | 口径 |
|----|------|
| UI | 工作台（`WorkbenchLayout`）**右下角悬浮球**；点击展开聊天窗；可关闭；不挡主流程 |
| 能力 | 用户提问 → 检索知识库 → 生成回答；**仅回答本工作台相关**；闲聊 / 竞品 / 无关编程题等 → **固定拒答话术** |
| 知识源 | 本仓新增一份 **Markdown《电商商品视觉工作台使用教程》**（见 §6），切块后写入向量库；本版以该文档为主语料（可后续加 FAQ 附录） |
| 示例问题须能答 | 「我在哪个位置使用生成图片功能？」「文案生成怎么计费？」「怎么升级到钻石会员？」等 —— 教程正文必须覆盖创作入口、积分消耗、会员等级规则等 |
| 会话 | 本版可做**单页短记忆**（最近若干轮）或无记忆首版；不做 rag102 级集合管理后台 |

#### 2.3.1 框架选型结论（建议默认 A）

| 方案 | 说明 | 建议 |
|------|------|------|
| **A. LangChain（+ 向量库）** | 本仓已用 `langchain-core` / `langchain-openai` / LangGraph；Agent 规划与 DashScope 兼容层已通 | **默认采用** |
| B. LlamaIndex（对齐 rag102） | rag102 全套管道成熟，但会新增 `llama-index-*` 大依赖族，与现有 LangChain/LangGraph **双栈并存**，维护成本高 | 本版不采用；仅参考其「文档→切块→检索→拒答边界」产品设计 |

**向量库建议**：本机持久化 **Chroma**（或等价轻量库），目录如 `backend/data/rag_chroma/`；embedding 走 DashScope 兼容接口（与现有 Key 共用）。不引入 Neo4j / GraphRAG / Tavily 联网。

**拒答策略**：系统提示 + 检索分数阈值（无命中或低相关则拒答）；禁止编造工作台不存在的功能。

## 4. 验收标准

### 4.1 文案生成

1. 侧栏在创作与编辑之间可见「文案生成」，进入 `/copywriting`。  
2. 仅文本可生成；带图（上传或选素材）亦可生成，结果含标题/正文/标签类结构。  
3. 成功扣积分（非 demo）；积分不足有明确提示。  
4. 实现可追溯至本仓服务与路由，而非粘贴 demo03/04 工程。

### 4.2 多图差异化

1. 创作页选 1 张：行为与 v11 一致。  
2. 选 2 或 4 张：生成的候选图**不应整图雷同**（允许同主题）；`params.prompt_variants`（或等价）长度为 N。  
3. Mock 下也能看出差异（便于无 Key 冒烟）。

### 4.3 AI 客服

1. 工作台右下角悬浮球可开可关聊天窗。  
2. 教程中已写明的入口 / 计费 / 会员问题能答到要点。  
3. 明显无关问题（如「今天股市怎么样」「帮我写 Python 排序」）拒答。  
4. 未登录不进入工作台则不可用（与现网 RequireAuth 一致）。

**验收一句话**：多图不再「复印机」；多一条文案生产线；右下角客服能按教程答工作台问题并拒答域外。

## 5. 数据 / 计费 / API 设计（摘要）

### 5.1 积分（建议默认，确认项）

| 动作 | 建议扣分 | 说明 |
|------|----------|------|
| 文案生成（每次成功） | **40**（`COST_COPYWRITING`） | 介于签到与 Agent 之间；可配置化顺延 |
| 文生图 | 维持 `COST_GENERATION`（按次或按张以现网为准；多图改写**不另扣** LLM 改写费，避免体感「隐形收费」） | 改写成本计入运营，不向用户单列 |
| 客服问答 | **0**（本版） | 控成本靠限流；若滥用再加轻量扣分 |

日 AI 配额：文案生成 **计入** 1 次；客服问答 **默认不计入**（确认项）。

### 5.2 API 前缀（建议）

```text
/api/copywriting              POST 生成文案（可流式另开 /stream）
/api/assistant/chat           POST 客服一轮问答
/api/assistant/chat/stream    POST/GET SSE（可选）
```

文生图仍走现有 `/api/generations`；改写在 Worker 内完成，契约可对前端透明。

### 5.3 索引构建

```text
# 开发 / 部署后执行一次（或启动时检测空库自动建）
python -m app.rag.build_index   # 名称以实现为准
```

语料路径固定指向教程 MD；更新文档后需重建索引。
