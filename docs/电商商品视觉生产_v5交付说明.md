| 版本 | 里程碑 | 用户能感知到什么 |

| v4 | M3 | 自然语言计划 → 确认执行 |

v5 补上「没有成片也能开干」的第二条入口：生图结果落成 **与上传同源的 `assets`**，再走已有会话 / 工具 / Agent，**不重写修图链路**。

## 2. 为什么第五版做「创作页 + 文生图」？

### 2.1 原则（延续 v1～v4）

1. **每版可演示**：验收题是「写一句商品图描述 → 看到候选图 → 点进编辑器能修」，不是半截 Provider。  
2. **Provider 可切换**（规划书 8.5）：`IMAGE_PROVIDER=mock|dashscope`；前端提供 **Mock / 真实生图** 切换（对齐 v4 规划器双按钮体验）。  
3. **耗时任务进队列**：真实生图数秒～数十秒，走 **ARQ Worker** + 进度（SSE 或轮询）；mock 也可入队以统一路径。  
4. **存储与会话复用 v2**：生成结果 = 新 `assets` 行 + 本地 `data/objects/`；进编辑器 = 已有 `POST /api/sessions`。  
5. **不碰 Agent/工具内核**：创作页是新入口；编辑器内仍用 v3 工具栏 + v4 Agent。

### 2.2 v5 明确不做（留给后续版本）

| 不做 | 放到哪一版 | 原因 |
|------|------------|------|
| 矩形/笔刷选区、局部 inpaint | v6 | 画布交互加重 |
| 主体/背景拆层、图层面板 | v7 | 图层模型后续扩展 |
| 强制登录、COS、应用 Docker 全量 | v8 / 增强 | 不阻塞「能生图」 |
| 图生图 / 扩图 / 超分 / 营销多 kind | 增强 | 一期只做「文生图 → 进编辑器」 |
| 批量套版、投放多尺寸流水线 | 增强 | 参考仓库有，本期裁掉 |
| 改写 Agent 去「调用生图工具」 | 增强 | 先独立创作页，避免范围膨胀 |

## 3. 第 5 版要完成什么？（验收标准）

完成 v5 后，你应能：

1. 落地页或导航可进入 **创作页**（`CreatePage`）。  
2. 输入中文 prompt（可选尺寸、张数），选择 **Mock** 或 **DashScope**，点击生成。  
3. `POST /api/generations` **立即返回** `generation_id`（不长时间堵死 HTTP）。  
4. Worker 执行生图；前端通过 **SSE**（建议 `GET /api/events/{generation_id}` 复用约定）或轮询看到进度。  
5. 完成后展示 **候选图网格**（至少 1～4 张）；每张对应已落库的 `asset_id`。  
6. 点击某张候选图 → 创建编辑会话 → 跳转 `/editor/:sessionId`，画布显示该图。  
7. 在编辑器内仍可用工具栏 / Agent（回归 v3/v4）。  
8. 无 Key 时 Mock 可完整演示；有 Key 时可切真实生图。  
9. README 写明 `IMAGE_PROVIDER` / 生图模型变量；提交 `version5`，tag 建议 `v5.0.0`。

**验收一句话**：创作页写「白色背景的运动鞋主图」→ 出候选图 → 点进编辑器 → 提亮/去背或 Agent 修一下。

## 4. 主流程（用户路径）

```text
用户打开 /create
  → 输入 prompt，选 Mock 或 DashScope，点「生成」
  → POST /api/generations
       { prompt, width, height, count, image_provider? }
  → services/generation：写 generation_runs(queued) → ARQ enqueue
  → 立即返回 { generation_id }

Worker：
  → status=running
  → ImageProvider.generate(...)（mock 色块图 / dashscope 真模型）
  → 每张图 put storage + insert assets
  → 更新 generation_runs.result_asset_ids，status=succeeded
  → Redis publish progress / completed

前端：
  → 订阅进度 → 展示候选网格
  → 用户点选一张
  → POST /api/sessions { asset_id }（v2 已有）
  → navigate /editor/{sessionId}
  → 后续精修走 v3/v4
```

## 6. 后端：v5 要完成哪些文件？

### 6.1 分层为何这样切

| 层 | 职责 | 为什么 |
|----|------|--------|
| `providers/*_image` | 纯「prompt → 图片字节」 | mock/真模型可替换；可单测 |
| `services/generation.py` | 落库、入队、写 asset | 事务与用例边界 |
| `tasks/generation.py` | Worker 调 Provider | API 不被生图拖死 |
| `routers/generations.py` | HTTP | 薄路由 |
| 既有 `assets` / `sessions` | 结果入库与进编辑器 | **零重写** |

### 6.2 ImageProvider 最小协议（对齐参考仓库，裁剪）

参考仓库 `GenerateRequest` / `ImageProvider.generate`；v5 **只要求 generate**，edit/upscale 不做。

```text
GenerateRequest:
  prompt: str
  width: int
  height: int
  count: int          # 建议 1～4
  negative_prompt?: str

ImageProvider.generate(request) -> list[bytes]
```

| Provider | 行为 |
|----------|------|
| `mock` | Pillow 按 prompt 哈希生成稳定色块/几何占位图（对齐参考仓库 mock 思路） |
| `dashscope` | 调用百炼文生图（`TEXT_TO_IMAGE_MODEL`，如 `qwen-image-3.0-pro` 或当前可用模型名） |

### 6.3 `generation_runs` 表（建议）

| 字段 | 说明 |
|------|------|
| `id` | UUID，兼作任务/SSE 关联 id |
| `prompt` | 用户提示词 |
| `params` | JSONB：width/height/count/negative_prompt 等 |
| `image_provider` | `mock` / `dashscope` |
| `status` | `queued` / `running` / `succeeded` / `failed` |
| `progress` | 0～100 |
| `result_asset_ids` | JSONB 字符串数组 |
| `error` | 失败信息 |
| `created_at` / `finished_at` | 时间 |

> 一期可不建独立「generations 业务表」以外的复杂关联；候选图全部进 `assets`，与上传图同等待遇。

### 6.4 接口契约（v5 冻结范围）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/generations/provider-options` | 默认 provider、dashscope 是否可用（供前端双按钮） |
| POST | `/api/generations` | body → `{ generation_id, status }` |
| GET | `/api/generations/{id}` | 状态、进度、`result_asset_ids` |
| GET | `/api/events/{id}` | **复用** SSE（progress/completed/error） |

进编辑器继续用：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/sessions` | `{ asset_id }`（v2） |
| GET | `/api/assets/{id}/file` | 显示候选图缩略/大图 |

**请求体示例**：

```json
{
  "prompt": "白色背景的运动鞋电商主图，居中，光线柔和",
  "width": 1024,
  "height": 1024,
  "count": 2,
  "image_provider": "mock"
}
```

### 6.5 与参考仓库的对齐与差异

| 点 | 参考仓库 | image100 v5 |
|----|----------|-------------|
| ImageProvider | generate/edit/upscale | **只做 generate** |
| mock 占位图 | 有 | **对齐思路**（哈希稳定构图） |
| dashscope 生图 | 有 | **对齐**；模型名用配置 |
| 创作页 | 有 | **对齐**：生成 → 选图 → 编辑 |
| 营销多类型 / 批量 | 有 | **不做** |
| 异步 | ARQ 等 | **对齐**：入队 + 进度 |

## 8. 进程与启动方式

仍为 **三进程**（与 v3/v4 相同）：

```bash
# API
uvicorn app.main:app --reload --host 0.0.0.0 --port 7302

# Worker（必须：生图任务在此执行）
python -m arq app.worker.WorkerSettings

# 前端
npm run dev
```

**新增配置示例**：

```env
IMAGE_PROVIDER=dashscope
TEXT_TO_IMAGE_MODEL=qwen-image-3.0-pro
# 复用已有 DASHSCOPE_API_KEY（系统环境变量即可）
```

> 注意：规划器用的 `DASHSCOPE_BASE_URL`（兼容模式 `/compatible-mode/v1`）与 **生图原生 API** 可能不是同一路径；实现时按百炼文档区分，不要假设 Chat 兼容端点能直接文生图。
