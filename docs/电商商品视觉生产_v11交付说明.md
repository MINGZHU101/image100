## 2. 相对 v10 的用户侧变更

### 2.1 新手礼包（替代注册自动到账 2000）

| 项 | v10 | v11 |
|----|-----|-----|
| 注册送分 | 注册成功立刻 +2000（`register_bonus`） | **取消自动到账** |
| 领取方式 | 无感知 | 个人中心总览页展示**礼包图标**；点击打开弹窗；点「马上领取」→ +2000 |
| 次数 | — | **每用户一生一次**；已领则图标灰态或显示「已领取」 |
| 流水 | `register_bonus` | 改为 `newbie_gift`（备注「新手礼包」） |

**交互要点**（对齐你提供的参考图）：

1. 入口：个人主页（`/account`）显著位置放礼物盒图标（可用你提供的图标资源，或 SVG 近似）。  
2. 弹窗：标题「新手大礼包」+ 简短卖点文案 + 「马上领取」主按钮；可展示三项利益点（如：起步积分 / 可签到加成 / 可邀请好友——文案可改）。  
3. 领取成功：Toast + 刷新积分；关闭弹窗。  
4. 已领取再点：提示「礼包已领取」或直接展示已领状态。

### 2.2 登录页：用户 / 管理员切换

- 默认仍是**用户登录**。  
- 增加切换：「用户登录 | 管理员登录」（注册仅用户侧）。  
- 管理员默认账号：**`admin` / `admin123456`**（迁移种子；生产环境必须改密，文档写明）。  
- 管理员登录成功 → 进入 **`/admin`** 管理台，不进用户工作台。  
- 用户 Cookie / JWT 带 `role=user|admin`；管理 API 校验 `admin`。

## 3. 管理端范围

### 3.1 界面骨架（模版取舍）

综合你提供的三张后台截图，本仓采用：

```text
/admin
├── 顶栏：产品名、当前管理员、退出
├── 左侧深色导航（可折叠子菜单）
└── 右侧：筛选条 + 表格 + 分页 + 抽屉/弹窗表单
```

| 参考图能力 | 本版是否采用 |
|------------|--------------|
| 侧栏多级菜单 + 高亮当前项 | **采用** |
| 顶栏搜索 / 消息铃铛 | 顶栏可做简化；消息铃铛 **降级**（可选公告入口） |
| 表格 + 编辑/删除按钮 + 分页 | **采用** |
| 复杂权限树 / 用户组矩阵 | **简化**：v11 仅「超级管理员」一种角色；用户组 **顺延** |
| 服务器信息大盘 | **可选**：仪表盘放业务指标即可 |

路由建议：

| 路径 | 页面 |
|------|------|
| `/admin` | 仪表盘 |
| `/admin/users` | 用户管理 |
| `/admin/points` | 积分与余额流水 |
| `/admin/invites` | 邀请概览 |
| `/admin/sessions` | 会话/素材概览（只读） |
| `/admin/announcements` | 公告管理 |
| `/admin/settings` | 运营参数 |
| `/admin/admins` | 管理员账号 |
| `/admin/audit` | 操作日志 |

### 3.2 必须做的基本功能

| 模块 | 能力 |
|------|------|
| **仪表盘** | 用户总数、今日注册、今日签到、今日 AI 次数、积分发放/消耗汇总、余额充值汇总 |
| **用户管理** | 列表（账号/用户名/会员/余额/积分/注册时间）；关键词搜索；按会员筛选；查看详情（流水摘要）；**冻结/解冻**；**手动调整积分**（正负，必填备注）；**手动调整余额**（正负，备注） |
| **积分/余额流水** | 全站流水查询（用户、类型、时间范围）；只读 |
| **邀请** | 已领取邀请奖励的用户列表；有效邀请码抽查（Redis 现况可简化为「近期成功记录」） |
| **会话概览** | 按用户查看会话数 / 最近更新；禁止越权改内容（只读） |
| **管理员** | 种子 admin；可改自己密码；可新增次级管理员账号（同为 admin 角色，v11 不做细粒度 RBAC） |
| **操作日志** | 记录管理员关键动作（调分、冻结、改配置、发公告） |
| **运营参数** | 可配置：新手礼包积分、签到表、兑换汇率、日配额表、模拟充值上限（写入 DB 或配置表；缺省回落 `membership_rules` 常量） |

### 3.3 建议一并做的进阶功能

| 模块 | 能力 | 说明 |
|------|------|------|
| **公告** | 发布/下线公告；用户端个人中心或工作台顶条展示最新一条 | 提升运营感 |
| **批量发分** | 按账号列表或「全体未冻结用户」发放积分 | 活动运营 |

## 4. 验收标准

### 4.1 用户侧

1. 新注册用户积分初始为 **0**（无自动 2000）。  
2. 个人中心可见新手礼包入口；领取一次得 2000；流水为 `newbie_gift`。  
3. 重复领取被拒绝。  
4. 登录页可切换管理员模式；用 `admin/admin123456` 进入 `/admin`。  
5. 普通用户访问 `/admin/*` → 403 或跳转。

### 4.2 管理端

1. 仪表盘数字与库内统计一致（允许短延迟）。  
2. 能搜索用户、冻结后该用户无法登录工作台（管理端仍可查）。  
3. 调积分/余额有流水与操作日志。  
4. 可改运营参数并在用户侧生效（至少：礼包积分、兑换汇率其一可验证）。  
5. 可发一条公告，用户端能看到。

**验收一句话**：用户靠礼包感知起步积分；管理员有独立入口与后台，能管用户与积分运营。

## 5. 数据与鉴权设计（摘要）

### 5.1 用户表增量

| 字段 | 说明 |
|------|------|
| `newbie_gift_claimed` | bool，是否已领新手礼包 |
| `is_frozen` | bool，冻结 |
| `token_version` | int，强制失效会话 |
| （已有）`wallet_balance` / `points_*` | 沿用 v10 |

注册流程：**不再**调用 `REGISTER_BONUS` 入账。

### 5.2 管理员

| 方案（建议默认 A） | 说明 |
|--------------------|------|
| **A. 独立 `admins` 表** | 与 `users` 分离，避免 admin 占用业务用户名空间 |
| B. users 表加 `role` | 实现快，但业务用户与管理员混表 |

默认 **A**：`admins(id, username, password_hash, …)`；种子 `admin`。

### 5.3 API 前缀

```text
/api/auth/*              用户登录注册
/api/auth/admin/login    管理员登录
/api/account/newbie-gift 领取礼包
/api/admin/*             管理端接口（需 admin JWT）
```

Cookie 可与用户端分名：`image100_session`（用户）/ `image100_admin_session`（管理员），避免串号。
