## 1. 第三版要解决什么问题？

v2 只证明「上传后画布能看见商品图」。v3 要把编辑器从「相册预览」变成「能干活的修图台」：

1. **工具能点**：工具栏至少含提亮、去背景、水平翻转、导出；工具定义集中在 ToolRegistry。  
2. **执行不堵 API**：`POST .../tools/{name}` 只写 `tool_runs` 并入 ARQ 队列，立即返回 `run_id`。  
3. **进度能看见**：Worker 经 Redis Pub/Sub 发事件，前端 SSE 订阅 `progress` / `completed` / `error`。  
4. **结果回画布**：成功后写新 asset、更新 `session.document` 主图层；前端重拉会话刷新 Konva。  
5. **结果能带走**：`GET /api/sessions/{id}/export` 同步下载当前主图层。

## 4. 后端完成了什么？

### 4.1 能力清单

1. 依赖增加 `arq`；配置增加 `matting_provider`（本期仅实现 `mock`）。  
2. `tool_runs` 表记录每次工具调用（status / progress / params / result_asset_id / error）。  
3. ToolRegistry 注册 3 个入队工具：`adjust_image`、`remove_background`、`flip_layer`；导出走同步 HTTP。  
4. `services/tools.invoke_tool`：校验会话与参数 → insert queued → ARQ enqueue（`_job_id=run_id`）。  
5. Worker 执行 handler：读主图层 → Pillow 处理 → 新 asset + 更新 document → Pub/Sub 终态。  
6. SSE：`GET /api/events/{run_id}`；已结束的 run 立即回放终态。  
7. 导出：读当前主图层文件流，`Content-Disposition: attachment`。

| 项 | 说明 |
|----|------|
| **一句话** | Worker 发进度，SSE 路由订阅同一频道。 |

**和谁联动**：`services/runs.report_progress` / `mark_succeeded` / `mark_failed` → publish；`routers/events` → subscribe。

## 6. 后端调用关系总图

```text
  浏览器 / 前端
       │
       ▼
  routers/tools ──► services/tools ──► tool_runs(queued)
       │                  │
       │                  └──► queue.enqueue_tool_run ──► Redis(ARQ)

  routers/events ◄── events.subscribe ◄── Redis Pub/Sub
       ▲
       │ publish
  services/runs ◄── tools/* handler ◄── tasks/tools.execute_tool_run
       │                                      ▲
       ├── edits/pixels                         │
       ├── storage + assets 新行                 │
       └── 更新 edit_sessions.document     Worker 进程
                                              (worker.py)
```

### 一次「点去背景 → 画布更新」时序

1. 前端 `POST /api/sessions/{id}/tools/remove_background` `{params:{}}`。  
2. `services/tools` 校验 → insert `tool_runs` → ARQ enqueue → 返回 `run_id`。  
3. 前端 `EventSource(/api/events/{run_id})`，显示进度条。  
4. Worker 取 job → `status=running` → 读主图层 → mock 去背 → 写新 PNG asset。  
5. 更新 `document.layers[0].asset_id` → publish `progress` / `completed`。  
6. 前端收到 `completed` → `GET /api/sessions/{id}` → CanvasStage 换新 `imageUrl`。  
7. 用户点导出 → `GET /api/sessions/{id}/export` 下载当前主图层。

```text
  → progress 更新 ProgressBar
  → completed        → getSession() 刷新 document
  → CanvasStage 加载新 /api/assets/{new_id}/file
  → 点「导出」       → GET /api/sessions/{id}/export 下载
```

## 8. 端口与数据落点
