> **一句话目标**：**迁入原仓库前端 UI → 已实现后端接口对齐并接通 → 腾讯云 COS 可切换 → 其余能力占位/顺延**  
> **关联文档**：  
> - `电商商品视觉生产_版本规划与v1交付说明.md`

## 1. v8 在整条版本线里的位置（口径）

```text
v1～v7 本仓自研前端 + 后端主链路已通
              ↓
★ v8：原仓前端 + 接口对齐 + COS（本文）
              ↓
v9+：Docker / 真登录 / 批量 / 营销图 / 未对齐的原仓能力 …
```

| 版本 | 原规划 | **本期实际** |
|------|--------|--------------|
| v7 | M6 图层 | 已交付（本仓简易前端） |
| **v8（本文）** | ~~仅 Docker~~ | **① 原仓前端迁入 ② 已实现 API 对齐接通 ③ COS** |
| v9+ | Docker / 增强 | Docker、真鉴权、Batch/Marketing 后端、未做工具等 |

**原则**：前端以原仓观感为准；后端**只补齐「前端主路径已依赖、且本仓 v1～v7 已有能力」的契约差异**；原仓有、本仓尚未实现的能力 → **UI 可保留入口但降级/占位**，逻辑放到后续版本。

## 2. 为什么第八版做这三件事？

### 2.1 原仓前端迁入

本仓 v2～v7 前端是「能演示」的精简版；原仓已有完整 Workbench 布局、编辑器组件、创作/候选/落地等页面。v8 把 **UI/交互资产**迁过来，避免继续在两套前端上分叉。

### 2.2 已实现后端接口对齐

原仓前端假定的 API 形状（路径、字段名、鉴权头、会话详情结构等）与本仓不完全一致。v8 **不为「原仓全部功能」重写后端**，而是：

1. 列一张「本仓已有能力 ↔ 原仓前端调用」对照表；  
2. 对主路径差异做 **适配层**（优先改本仓 API 契约贴近原仓，或在前端 `api/*` 做薄适配）；  
3. 未实现能力不硬接，避免半截 500。

### 2.3 腾讯云 COS

存储上云，local 可回退；与前端迁入正交，可并行。

### 2.4 明确不做 / 顺延（本期）

| 不做 | 放到哪 | 说明 |
|------|--------|------|
| 应用 Docker / compose / nginx | v9 | 用户已要求暂缓 |
| 真登录注册（JWT 全站强制） | v9+ | 本期用 **演示鉴权桩** 满足原仓 `RequireAuth` |
| Batch / Marketing **后端业务** | v9+ | 前端可留路由，进页显示「即将推出」或禁用 |
| 原仓全量工具（云端 erase/replace、SAM、OCR 字层等） | 后续 | 工具栏只暴露本仓 Registry 已有工具 |
| 整仓复制原仓后端 | 不做 | 本仓 v1～v7 架构保留 |
| 把本仓 Agent/生图逻辑推倒重写成原仓 | 不做 | 契约对齐即可 |

## 3. 第 8 版要完成什么？（验收标准）

### 3.1 必须 A：原仓前端迁入并跑通主路径

1. `frontend/` 以原仓 `frontend/src`（及必要的 `package.json` 依赖、样式、别名 `@/`）为基底迁入。  
2. 品牌文案可改为 image100 / 电商商品视觉（不要求像素级照搬营销文案）。  
3. 本地 `npm run dev`（7301）可打开原仓风格落地页与工作台布局。  
4. **主路径可演示**（与本仓已实现能力对应）：  
   - 上传 / 建会话 → 编辑器  
   - 工具栏：提亮、局部提亮、去背、翻转、拆层、导出  
   - 选区（矩形/笔刷）  
   - 图层面板显隐 / 选中  
   - Agent：规划 → 确认 → 执行  
   - 文生图创作 → 候选 → 进编辑器（若原仓拆成 Create/Candidates，对齐本仓 generations）  
5. 原仓有、本仓无后端的页面（如 Batch、Marketing、真登录）：**可进路由但不报崩**（占位页或 toast「后续版本」）。

### 3.2 必须 B：已实现接口与原仓前端对齐

1. 产出并维护 `docs/v8_API对照表.md`（或交付说明附录）：路径、方法、关键字段、本仓现状、适配策略。  
2. 编辑器主路径 **零控制台硬错误**（404/422 仅出现在未实现功能的明确提示）。  
3. 鉴权：原仓前端带 Token 时，本仓提供 **演示模式**（例如固定 DEMO 用户、开发用 mock token / 关闭强制校验），不阻塞联调。  
4. SSE / 工具进度：原仓若订阅 events，本仓现有 `/api/events/{id}` 能驱动进度条。

### 3.3 必须 C：腾讯云 COS

1. `STORAGE_BACKEND=cos` + COS 配置可启动；`health.storage=ok`。  
2. 上传/拆层产物进桶；画布经 API 代理可读。  
3. `local` 可回退。  
4. README / `.env.example` 写清切换方式。

### 3.4 建议顺延（不再作为 v8 默认增强）

原 v8.0 中的 `promote_object_to_layer`、rembg、「显示全部」等 → **默认放到 v8 之后或有余力再做**（见 §14），避免与「前端迁入」抢带宽。

**验收一句话**：打开原仓风格前端 → 上传商品图进编辑器 → 拆层/选区/Agent/生图主路径可用 → 可切 COS。

## 5. 前端迁入范围（相对原仓）

### 5.1 迁入（必须）

| 区域 | 说明 |
|------|------|
| `pages/` | Landing、Create、Candidates、Editor；Auth/Batch/Marketing **可迁入但降级** |
| `layouts/` | WorkbenchLayout；RequireAuth → **演示鉴权桩** |
| `components/editor/` | 画布、工具栏、图层面板、对话、选区等 |
| `api/`、`hooks/`、`stores/`、`lib/` | 按需改接点 |
| `index.css` / 静态资源 | 视觉一致 |
| 构建 | Vite 别名 `@/`、依赖与原仓对齐（React/Konva 等） |

### 5.2 替换 / 删除

| 本仓旧前端 | 处理 |
|------------|------|
| 现有精简 `pages/*`、`components/editor/*` | **被原仓版本替换**（可先分支备份，不必双轨长期维护） |
| 本仓特有文案/端口代理 | 保留 `vite.config` 代理到 7302 |

### 5.3 前端适配策略（推荐）

1. **优先改前端 `api/*`**：把请求路径/字段映射到本仓已有接口（改动面集中）。  
2. 若原仓多处写死契约、映射成本过高 → **本仓增加兼容路由或响应字段**（薄适配，不重写领域模型）。  
3. 禁止：为迁前端而引入原仓全量 ORM/工具注册表。

## 6. 后端对齐范围（仅「已实现」）

### 6.1 本仓已有、需与原仓前端对上的能力

| 能力 | 本仓现状（约） | 对齐注意点（示例） |
|------|----------------|-------------------|
| 健康检查 | `GET /api/health` | 字段名是否一致 |
| 上传资产 | `POST /api/assets` | 响应是否含 url/id |
| 会话 | `POST/GET /api/sessions` | 原仓 `SessionDetailOut`（wall、can_undo…）本仓可能无 → 前端降级或后端补最小字段 |
| 工具调用 | `POST .../tools/{name}` 或原仓 `POST .../tools` | **路径与 body 形状**必须统一一种；建议本仓增加与原仓兼容的 invoke 入口或前端改调本仓 |
| 运行/SSE | `/api/events/{id}`、`/api/runs` | 事件字段 `progress/completed/error` |
| Agent | `/api/agent/...` vs 原仓 `.../messages` | **二选一适配**：前端改调本仓 agent，或本仓加 messages 别名转发到现有 agent_runs |
| 文生图 | `/api/generations` | 与 Create/Candidates 页对接 |
| 选区 | `PATCH .../selection` | 原仓为 prepare/strokes/points + mask asset → **本期用适配**：前端选区写本仓 JSON selection，或后端补最小 selection API |
| 图层 | `PATCH .../layers`、`split_layers` | 原仓 LayerPanel 字段（transform 等）缺省用默认值 |
| 导出 | `GET .../export` | 原仓 zip/多资产 → 本期单图 PNG 即可，前端改调用 |
| 存储 | local + **COS（本期新增）** | 对前端透明 |

### 6.2 原仓有、本仓无 → 本期不实现后端

| 原仓能力 | v8 前端处理 |
|----------|-------------|
| Auth 注册登录 | 演示登录 / 自动注入 DEMO 用户 |
| undo/redo/history | 按钮隐藏或 disabled + 提示 |
| selection mask 资产流 | 走本仓 selection JSON |
| batches / marketing | 占位页 |
| 部分工具名 | 工具列表以本仓 Registry 为准过滤 |

### 6.3 COS（与前节相同，略）

- SDK：`cos-python-sdk-v5`  
- `STORAGE_BACKEND=local|cos`  
- 读图默认仍 API 代理

## 8. 推荐开发顺序

1. **拉分支** `version8`；备份本仓旧前端（tag 或目录归档说明）。  
2. **迁入原仓前端**，先能静态打开布局（鉴权桩放行）。  
3. 写 **API 对照表**：只覆盖主路径。  
4. **逐页接通**：Landing → 上传/会话 → Editor 工具 → 选区 → 图层 → Agent → Create/Candidates。  
5. 未实现路由做成占位。  
6. **COS** 落地并回归 local。  
7. README、联调清单、tag `v8.0.0`。
