## 1. 第四版要解决什么问题？

v3 证明「点工具栏能修图」。v4 要把产品升级为「自然语言驱动」：

1. **能说话**：编辑器右侧输入电商话术（如「去掉背景，再提亮一点」）。  
2. **能出计划**：LangGraph `plan → verify` 产出结构化步骤（仅 `agent_exposed` 工具）。  
3. **能切换规划器**：界面 **Mock / LLM** 两按钮，按次选择规则规划或 DashScope。  
4. **能确认再跑**：PlanCard 确认后，Worker 严格串行入队 v3 工具；未确认不产生 `tool_runs`。  
5. **结果回画布**：各步仍走 ARQ +（可选）SSE；全部 `done` 后刷新会话。

## 4. 后端完成了什么？

### 4.1 能力清单

1. LangGraph 最小图：`START → plan → verify → END`（课件 ③+⑦）。  
2. 规划器：`mock`（关键词规则）与 `dashscope`（`ChatOpenAI` 兼容端点 + `bind_tools`）。  
3. 请求体可带 `planner_provider` 覆盖默认；无 Key 时选 dashscope 返回 400。  
4. `agent_runs` 记录 goal / reply / plan / status / planner_provider / tool_run_ids。  
5. 确认后 ARQ `execute_agent_plan`：严格串行 `invoke_tool`，等 succeeded 再下一步。  
6. 取消：`planned`（及未开跑的 `confirmed`）可 cancel。  
7. ToolSpec 增加 `agent_exposed`；Agent 只绑定三个 v3 工具。

### 4.2 依赖增量

| 包 | 用途 |
|----|------|
| `langgraph` | StateGraph |
| `langchain-core` | Message、工具 schema |
| `langchain-openai` | DashScope OpenAI 兼容 Chat |

### 4.3 环境变量（v4）

| 变量 | 含义 | 示例 |
|------|------|------|
| `PLANNER_PROVIDER` | 默认规划器 | `dashscope` |
| `DASHSCOPE_API_KEY` | 百炼 Key（建议系统环境变量） | （不入库） |
| `DASHSCOPE_BASE_URL` | 兼容端点 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `PLANNER_MODEL` | 规划模型 | `qwen-plus` |

### 4.4 接口一览（相对 v3 新增）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/agent/planner-options` | 默认值、dashscope 是否可用 |
| POST | `/api/sessions/{id}/agent/runs` | `{goal, planner_provider?}` |
| GET | `/api/sessions/{id}/agent/runs/{agent_run_id}` | 查询状态 |
| POST | `.../confirm` | 确认 → 入队串行执行 |
| POST | `.../cancel` | 取消 |

### 4.5 计划 JSON

```json
{
  "steps": [
    {"id": "s1", "tool_name": "remove_background", "params": {}, "depends_on": []},
    {"id": "s2", "tool_name": "adjust_image", "params": {"brightness": 0.2}, "depends_on": ["s1"]}
  ]
}
```

### 4.6 `agent_runs` 状态机

`planned` →（confirm）`confirmed`/`running` → `done`  
或 `failed` / `cancelled`。

## 6. 后端调用关系总图

```text
前端 Mock|LLM + goal
    → POST .../agent/runs
         → providers (mock|dashscope)
         → LangGraph plan → verify
         → agent_runs(planned)

前端确认
    → POST .../confirm
         → enqueue_agent_plan
              → Worker execute_agent_plan
                   → 循环 invoke_tool → execute_tool_run（v3）
                   → 更新 document / SSE
              → agent_runs(done|failed)
```

### 一次「去背再提亮」时序

1. 选 Mock 或 LLM，发送 goal。  
2. 返回两步计划 + PlanCard。  
3. 确认 → `execute_agent_plan`。  
4. 先 `remove_background` 成功，再 `adjust_image`。  
5. `status=done`，前端刷新画布。

## 7. 前端完成了什么？

### 7.1 能力清单

1. 右侧「自然语言修图」栏。  
2. **Mock / LLM** 切换；无 Key 时 LLM 禁用。  
3. 发送 goal → 展示 reply 与 PlanCard。  
4. 确认后轮询 `agent_runs` 至 done/failed，再刷新会话。  
5. 保留 v3 工具栏与导出。

### 7.2 关键文件

| 文件 | 作用 |
|------|------|
| `api/agent.ts` | planner-options / create / get / confirm / cancel |
| `hooks/useAgent.ts` | 规划器状态、提交、确认轮询 |
| `AgentConversation.tsx` | 切换按钮 + 输入 + 消息 |
| `PlanCard.tsx` | 步骤列表 + 确认/取消 |
| `EditorPage.tsx` | `editor-body` 画布 + Agent 双栏 |
| `index.css` | Agent / PlanCard / toggle 样式 |

### 7.3 联动

```text
选择 Mock 或 LLM
  → createAgentRun(..., planner_provider)
  → PlanCard 确认
  → confirmAgentRun → 轮询 getAgentRun
  → done → reloadSession → CanvasStage 换图
```
